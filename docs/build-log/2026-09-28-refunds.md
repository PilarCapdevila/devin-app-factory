## Decisions made without asking (listed in the plan, approved as written)

- Analysts (`alice`, `bob`) get no refunds permission.
- `support_agent` does **not** get `pii.reveal`: the permission is platform-wide and the KYC reveal
  route only checks `pii.reveal` + KYC `visibleWhere` (`{}` for non-analysts), so it would expose KYC
  applicant PII. Approvers reveal `customerEmail` when needed.
- `Refund` gains `updatedAt` and nullable `issuedAt` (drives the "issued today" tiles, UTC day).
- A new request for a `paymentId` is rejected (400) while another request for it is still pending;
  allowed after `RETURNED` (and after `ISSUED`, partial refunds).
- Seed is USD only; the request form accepts USD/EUR/GBP.
- Customer/payment fields are typed by the agent (no payment-lookup connector).
- Names: approval action `refunds.issue`; entity type `refunds.refund`; audit actions
  `refunds.refund.requested` / `refunds.refund.issued` / `refunds.refund.returned`.
- The mock connector runs inside the approval transaction (a failure after the call rolls back the
  ledger row too) and is idempotent on `idempotencyKey`.
- Summary tiles are a separate `GET /api/refunds/summary`; the request form is inline on the dashboard.
- `cardLast4` and `customerName` are not PII fields (`cardLast4` is already a last-4 value).
- The hard-coded "KYC Queue" link in the platform `AppShell` (not editable under the playbook) is
  still visible to Frank; clicking it yields Forbidden and an `access.denied` audit event.
